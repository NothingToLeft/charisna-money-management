CHARISNA MONEY MANAGEMENT v11.1 — QA REPORT
Tanggal pemeriksaan: 18 Juli 2026

RINGKASAN TEMUAN
Bug utama berasal dari parser v11.0 yang menganggap satu titik dengan tiga digit sebagai pemisah ribuan, tetapi menganggap “1.0000” sebagai angka desimal 1. Akibatnya, setelah tampilan mencapai 1.000, digit berikutnya membuat nilai kembali menjadi 1. Formatter tersebut sudah diganti dengan sistem berbasis digit mentah dan nilai numerik kanonis.

PERBAIKAN TAMBAHAN YANG DITEMUKAN SAAT AUDIT
- Kolom kosong sebelumnya dapat berubah menjadi 0 karena Number("") menghasilkan 0.
- Refresh kurs manual dapat membaca tampilan 1.000 sebagai 1.
- Input desimal koma sulit dimasukkan karena separator hilang pada setiap ketikan.
- Tombol backspace di dekat titik ribuan dapat terlihat tidak bekerja.
- Template transaksi mengubah value tanpa memperbarui nilai numerik formatter.
- Kategori legacy dapat hilang dari dropdown saat transaksi lama diedit.
- Rename kategori belum memperbarui kategori induk anak.
- Kurs yang tidak tersedia dapat ditampilkan sebagai 0.
- Launcher Windows masih memakai nama dan query cache v10.
- Pemeriksaan batas folder pada server lokal Windows terlalu longgar.
